# Infrastructure Security Exceptions

These are narrow exceptions for controllers that cannot perform their platform role
under the baseline application security context. They do not waive resource limits,
network isolation, image pinning, or monitoring where the upstream component supports
them. Phase 8 policy rules must encode only these named exceptions.

## Longhorn system workloads

| Workload | Required exception | Reason | Compensating controls |
| --- | --- | --- | --- |
| `longhorn-manager` | privileged host access | Manages block devices, mounts, and host storage paths | Dedicated `longhorn-system` namespace, upstream chart network policies, checksum-pinned chart archive, internal-only UI, and three-node replication |
| Longhorn CSI node and engine workloads | privileged, host PID/path/device access | CSI attachment and volume engines must interact with kubelet and the host storage stack | Restricted to the upstream Longhorn service accounts and namespace; no public route; hardware checks in the verification ledger |
| Longhorn pre-pull jobs | upstream security context | Prepares version-matched engine images on storage nodes | Short-lived jobs, pinned release, namespace isolation, and no external ingress |

The exception applies only to resources generated by the verified Longhorn `1.12.1`
chart. Application workloads using Longhorn volumes receive no privilege exception.
Longhorn's generated system workloads do not all expose application-style HTTP probes
or accept every baseline security-context field; the repository does not claim they do.

## Node exporter

| Workload | Required exception | Reason | Compensating controls |
| --- | --- | --- | --- |
| `monitoring-prometheus-node-exporter` | host network, host PID, and read-only host filesystem mounts | Node and filesystem metrics must be observed from the host namespaces | Exact chart workload only, digest-pinned image, no public Service, dropped capabilities, read-only root filesystem, resource bounds, probes, and namespace network policy |

The `monitoring` namespace therefore enforces the privileged PSA profile while auditing
and warning against restricted violations. This exception does not permit other
monitoring workloads to add host access or privileges. Phase 8 binds the policy
exception to the exact node-exporter controller and image.

## Review and expiry

Re-check these exceptions on every Longhorn or kube-prometheus-stack upgrade with
`helm show values`, rendered
manifests, and the pinned CRDs. Remove an exception when upstream supports the baseline.
Phase 8 must bind Kyverno exclusions to exact namespace, controller, and image patterns;
a wildcard exemption for `longhorn-system` is not acceptable.
