# Infrastructure Security Exceptions

These are limited exceptions for controllers that cannot perform their platform role
under the baseline application security context. They do not waive resource limits,
network isolation, image pinning, or monitoring where the upstream component supports
them. Policy and supply chain policy rules must encode only these named exceptions.

## Longhorn system workloads

| Workload | Required exception | Reason | Compensating controls |
| --- | --- | --- | --- |
| `longhorn-manager` | privileged host access | Manages block devices, mounts, and host storage paths | Dedicated `longhorn-system` namespace, upstream chart network policies, checksum-pinned chart archive, internal-only UI, and three-node replication |
| Longhorn CSI node and engine workloads | privileged, host PID/path/device access | CSI attachment and volume engines must interact with kubelet and the host storage stack | Restricted to the upstream Longhorn service accounts and namespace; no public route; hardware checks in the verification checklist |
| Longhorn pre-pull jobs | upstream security context | Prepares version-matched engine images on storage nodes | Short-lived jobs, pinned release, namespace isolation, and no external ingress |

The exception applies only to resources generated by the verified Longhorn `1.12.1`
chart. Application workloads using Longhorn volumes receive no privilege exception.
Longhorn's generated system workloads do not all expose application-style HTTP probes
or accept every baseline security-context field; the repository does not claim they do.

## Node exporter

| Workload | Required exception | Reason | Compensating controls |
| --- | --- | --- | --- |
| `monitoring-prometheus-node-exporter` | host network, host PID, and read-only host filesystem mounts | Node and filesystem metrics must be observed from the host namespaces | Exact chart workload only, digest-pinned image, no public Service, dropped capabilities, read-only root filesystem, resource bounds, probes, and namespace network policy |

The `monitoring` namespace therefore enforces the privileged PSA profile while auditing
and warning against restricted violations. This exception does not permit other
monitoring workloads to add host access or privileges. Policy and supply chain binds the policy
exception to the exact node-exporter controller and image.

## Policy and scanning controllers

| Workload | Required exception | Reason | Compensating controls |
| --- | --- | --- | --- |
| Kyverno controllers | Cluster-scoped read and admission RBAC | Admission and background evaluation require observing protected resources | Dedicated restricted namespace, HA replicas, digest pins, NetworkPolicy, Audit-first rollout |
| Trivy Operator | Cluster-scoped report and workload read RBAC | The operator discovers workloads and writes security-report CRs | Dedicated restricted namespace, digest pins, two-job concurrency cap, host collector disabled |

Neither controller is exempt from resource bounds, probes, container hardening, image
pinning, or namespace network isolation.

## Chaos Mesh daemon

| Workload | Required exception | Reason | Compensating controls |
| --- | --- | --- | --- |
| `chaos-daemon` | privileged container, host PID, runtime socket, `/sys`, and `/lib/modules` mounts | Pod, network, stress, and I/O injection require entering target process and network namespaces | Dedicated privileged `chaos-mesh` namespace, exact checksum-pinned chart, resource bounds and probes, no dashboard, namespace-filter enforcement, mTLS-independent namespace NetworkPolicy, and a separately confirmed experiment command |

Only `chaos-testing` carries `chaos-mesh.org/inject=enabled`. The GitOps application
does not include experiment objects, and the guarded runner refuses execution when any
other namespace opts in. The controller manager remains non-root, drops all
capabilities, uses a read-only root filesystem, and has no host access. The privileged
exception never applies to the sacrificial target or an application namespace.

## Review and expiry

Re-check these exceptions on every Longhorn, Chaos Mesh, or kube-prometheus-stack upgrade with
`helm show values`, rendered
manifests, and the pinned CRDs. Remove an exception when upstream supports the baseline.
Application policies use positive namespace profile labels rather than wildcard
infrastructure exclusions. A namespace must opt into the application profile, while
the stricter signature policy requires a separate supply-chain label.
